# Design: CampusClaw 首版基线

## Context

CampusClaw 是面向中小学的班级教研智能体平台。教师上传本班讲义，学生在本班范围内检索。
平台此前只有材料上传的设想，没有身份、权限和班级边界，无法支撑「跨班不可见」这一核心约束。
本 change 覆盖登录、角色权限、班级隔离、讲义入库与检索五块能力。

## Goals / Non-Goals

### Goals
- 身份来自服务端会话，客户端不能自报角色或班级
- 班级作为数据边界，在数据访问层强制，而不是在页面隐藏
- 讲义上传后状态可追踪：已上传、索引中、可用、失败
- 检索结果带来源（文件、位置），可回到原文核对

### Non-Goals
- 不做分布式部署与多租户隔离
- 不做混合检索与重排序，首版只做向量检索
- 不做讲义版本管理与协同编辑

## Decisions

### 决策 1：会话用 Bearer 令牌 + 服务端会话表

**选项**：Cookie 会话 / JWT 无状态 / 服务端会话表 + Bearer

**选择**：服务端会话表 + Bearer 令牌

**理由**：
- 课程明确要求 Bearer 令牌访问接口，便于用 Swagger 和脚本复现
- 服务端可撤销会话，登出和禁用账号立即生效；无状态 JWT 需要额外的黑名单
- 令牌只在服务端签发和校验，前端保存在当前标签页，不写入日志

### 决策 2：班级边界放在数据访问层

**选项**：页面隐藏 / 接口入参带 class_id / 会话读取 class_id 并在查询条件中强制拼接

**选择**：会话读取 + 数据访问层强制拼接

**理由**：
- 页面隐藏挡不住直接调接口，入参带 class_id 等于让调用方决定边界
- 会话里的班级是唯一可信来源，查询条件统一由此生成
- 跨班资源与不存在资源返回相同 404，避免泄漏「有这条数据」

### 决策 3：上传同步落库、异步建索引

**选项**：同步建索引 / 异步任务 / 只存原文不建索引

**选择**：同步保存原文与记录，异步建索引

**理由**：
- 大文件建索引慢，同步会让上传请求超时
- 原文先落库，索引失败时用户仍能下载原文，并可重试
- 状态机：`uploaded` → `indexing` → `ready` / `failed`，页面显示真实状态

### 决策 4：向量库选型

**选项**：Chroma（嵌入式）/ FAISS（本地索引）/ Qdrant（独立服务）

**选择**：Chroma

**理由**：
- 教学项目数据量小，不需要独立服务
- 支持元数据过滤，班级 ID 可作为过滤条件
- 嵌入式部署简单，后续需要时可平移到 Qdrant，接口层不暴露具体实现

## Risks / Trade-offs

- 班级隔离依赖每个查询都拼接班级条件，漏一处就是越权。缓解：把过滤放进统一的数据访问函数，并用越权用例回归。
- 异步索引存在中间状态，用户可能看到「索引中」。缓解：界面明确显示状态，不把中间态说成可用。
- 纯向量检索对精确术语不友好。缓解：首版接受，后续在 change 中增加混合检索。

## Migration Plan

首版无存量数据，直接建表。后续若增加字段，通过迁移脚本执行，不手工改库。
